# 公交行驶轨迹整理（路段匹配 + 站点驻留核对）

把一辆公交车一次行程的定位点，整理成可用于路段运行时间分析的有向路段行驶轨迹；
并支持分析员在网页上核对车辆是否曾在某站点**持续驻留**。
提供 FastAPI + SQLite 网页：上传有向路段 CSV 与定位点 CSV、设置匹配半径、查看逐点归属与路段序列；
录入站点参数后自动核对驻留并展示证据。

## 规则（与需求一一对应）

- 每个定位点只在**匹配半径内**的路段中取候选（点到有限线段的最短距离 ≤ 半径）。
- 相邻两点的路段只能：
  1. 保持同一路段；或
  2. 沿行驶方向进入下一段，且**上一段终点坐标 = 下一段起点坐标**（端点相接）。
- 在全程可连通的候选组合中，取**点到路段距离总和最小**者。
- 若不存在连通路径 → 待核，`reason=NO_CONNECTED_PATH`；
  若最小距离和对应**多条**路径 → 待核，`reason=AMBIGUOUS`；
  若某点半径内无路段 → 待核，`reason=NO_CANDIDATE`。
  三种情况都**不发布唯一轨迹**。
- 并列判定使用严格容差（绝对 1e-9 m + 相对 1e-12）；差在这个范围外即视为唯一。
- 端点相接的坐标比较按 1e-6 m 量化，避免浮点噪声。

## 站点驻留核对规则

- 网页录入：站点所属路段号、平面坐标（x, y）、判定半径、最短驻留时长（秒）、最大采样间隔（秒）。
- 核对只取**现行唯一轨迹**中**归属该路段**且**到站心距离 ≤ 判定半径**的定位点。
- 相邻符合点时间间隔全部 ≤ 最大采样间隔的连续段，首末时差 ≥ 最短驻留时长
  → **已驻留**，页面展示观察到的起止时刻与全部证据点（序号、时刻、坐标、到站心距离）。
- 符合点之间存在超限间隔 → **断采样**，拆成多段分别判断，**断采样不能拼成驻留**
  （`reason=GAP_EXCEEDS_LIMIT`，结论=证据不足）。
- 连续段最长首末时差仍不足 → 证据不足（`reason=SPAN_TOO_SHORT`）；
  无任何符合点 → 证据不足（`reason=NO_QUALIFYING_POINTS`）。
- 轨迹待核（无唯一轨迹）→ 无法核对（`reason=TRAJECTORY_UNDER_REVIEW`）。
  证据不足与无法核对都**不得给出已驻留结论**。
- 每条结论**绑定**所用轨迹结果编号、路网修订、定位点修订与匹配半径，页面可见。

## 修订与失效

- 路网、定位点各自维护递增修订号（r1、r2 …），每次上传是**整版替换**并立即成为当前版本；历史修订保留供追溯。
- 新版受理的同一事务里，依赖旧版的所有已发布结果被标记失效（`NETWORK_REPLACED` / `POINTS_REPLACED`），页面单独列出且标注“不得用于路段运行时间分析”。
- 改半径（`RADIUS_CHANGED`）同样使旧结果失效并安排重算。
- **驻留结论同步撤销**：路网/定位点换版或匹配半径变更的同一事务里，所有现行驻留结论一并撤销
  （页面单列“已撤销的驻留结论”，不得作为驻留依据）；新轨迹发布后，每个核对自动按新轨迹重核。
- 重算/核对任务的发布动作会再次核对“路网修订 / 定位点修订 / 半径”是否仍为当前值，且驻留核对还会
  检查所绑定的轨迹结果未被撤销；不一致则任务作废（`SOURCE_CHANGED_DURING_RECOMPUTE` /
  `SOURCE_CHANGED_DURING_CHECK`），**核对与匹配交错时绝不发布旧版结果**。
- 计算失败的任务回到 `pending` 并有指数退避重试；进程重启时把遗留的 `running` 任务（含驻留核对任务）
  重置为 `pending`，因此失败或重启后未完成的核对保持待核并可重试，不会丢失。

## 本地运行

```bash
python3 -m pip install -r requirements-dev.txt
uvicorn app.main:app --reload --port 8000
# 打开 http://localhost:8000
```

数据库默认在 `./data/track_matcher.sqlite3`，可用 `TRACK_MATCHER_DB` 覆盖。
`TRACK_MATCHER_WORKER=0` 只关闭后台计算线程（测试用）。

## Docker Compose

```bash
docker compose up --build
# 打开 http://localhost:8000
```

数据保存在命名卷 `track_matcher_data`。容器内为单进程（后台计算线程与 Web 在同一进程），SQLite 文件位于卷上。

```bash
python3 -m pytest -q
```

测试覆盖：平行路段择优、精确并列的歧义、反向/跳段不可连通、半径边界、断采样不能拼成驻留、
驻留结论的绑定与换版撤销、核对与匹配交错拒发旧版结论、失败/重启后核对保持待核并重试，

## 示例文件

`sample/` 下：

- `network.csv` + `points.csv`：两条平行路段，点更靠近北侧，应发布唯一轨迹 `N101 → N102 → N301`。
- `network_parallel.csv` + `points_parallel.csv`：两条互不相接的平行路，恰好形成并列最优 → 待核。
- `points_dwell.csv`：配合 `network.csv` 使用，车辆在 N101 段 (60, 0) 附近停留约 40 秒。
  上传后登记驻留核对：路段号 `N101`、坐标 `(60, 0)`、判定半径 `8` 米、最短驻留 `30` 秒、
  最大采样间隔 `25` 秒 → 应判定已驻留（观察窗口 00:00:20Z → 00:01:00Z，证据点 5 个）。
